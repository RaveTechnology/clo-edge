# SIP/RTP network experiment — 18 November 2026

This is an isolated network compatibility experiment. It does not add a SIP
balancer to the HTTP edge controller, qualify production telephony, or move any
customer data. Only synthetic identities and calls were used; no operator trunks,
telephone numbers, production DNS or production deployments were changed.

## Topology and runtime

A temporary two-node RKE2 cluster was provisioned through the existing Rancher:
one private control/media node and one VoIP worker, each with 2 shared vCPU,
4 GB RAM and a 20 GB boot volume. A dedicated NAT served private egress. The
worker received a previously reserved public IPv4 only after its persistent
pre-DNAT firewall was active. An isolated external cloud VM was the test peer.
The permanent Rancher remained at 2 vCPU / 8 GB.

Kamailio and rtpengine used host networking on the VoIP worker. FreeSWITCH used a
regular pod on the other node. Kubernetes node identities and Canal transport
stayed on the VPC network. The media plane did not pass through HAProxy, Traefik,
the CLO managed LB or the HTTP edge failover controller.

Tested versions: Rancher 2.15.3, node driver 0.1.0, UI 0.1.6,
RKE2 v1.36.5+rke2r1 with Canal, Kamailio 6.1.3, rtpengine 9.4.0.0 and
FreeSWITCH 1.10.12. The three telephony images were pinned to the existing
operator-supplied runtime digests. FreeSWITCH was imported privately and ran
with a fresh minimal configuration: no application configuration service,
production gateways, application credentials, recording uploader or customer data.
SIPp 3.8.0 was checked against the official release SHA256.

## Observed network requirement

The first INVITE using the worker's VPC address on the internal leg timed out.
Paired packet captures and the actual `FLANNEL-POSTRTG` rules showed that
host-to-remote-pod traffic was masqueraded to the worker's overlay address,
including a randomized source port. A direct OPTIONS probe reproduced this;
binding to the worker's own `flannel.1` address preserved its source port.

The corrected fixture bound Kamailio's internal SIP socket and rtpengine's
internal interface to that node-local overlay address. FreeSWITCH trusted only
that exact internal address, and reverse calls used it as their proxy. The
public socket and Kubernetes node IP stayed unchanged. No Flannel NAT or
cluster-wide routing rules were modified.

This is a deployment requirement for this Canal topology, not a universal CNI
rule. A deployable chart must discover and validate the current internal
interface, update trusted addresses on node replacement, and requalify the
behavior on CNI upgrades. The experiment used explicit lab configuration.

## Results

A bounded Python SIP client sent PCMU through the public media relay to the
private FreeSWITCH echo application. It checked the public SDP address, actual
RTP source, received sequence uniqueness, exact returned audio, and ACK/BYE
completion. SIPp independently completed a separate signalling call.

Here, “exact echo” means a 160-byte PCMU payload matches a cyclic alignment
of the repeated 20 ms source waveform, permitting codec frame-boundary phase
shifts. It does not map individual sent packets to received packets or measure
end-to-end delay.

| Transport | Requested duration | RTP sent | RTP returned | Exact echo frames |
| --- | ---: | ---: | ---: | ---: |
| UDP smoke | 5 s | 250 | 248 | 248 |
| UDP | 45 s | 2250 | 2248 | 2248 |
| TCP | 10 s | 500 | 498 | 498 |
| TLS | 45 s | 2250 | 2248 | 2248 |
| WSS | 10 s | 500 | 497 | 497 |

Received counts were 2–3 below transmitted counts per call; this experiment
did not localize those missing samples. These observations do not establish
zero packet loss, jitter bounds, throughput or an availability SLA. The long
calls retained audio and completed normally beyond the 32-second SIP interval.
A query correlated with the final WSS session counted 996 RTP packets across
the two relay legs and zero rtpengine RTP errors. This sampled counter is not a
whole-call loss measurement.

TLS and WSS used a fresh lab CA and a verified certificate IP SAN; certificate
verification stayed enabled. An untrusted CA failed verification. WSS carried
ordinary PCMU RTP: this did **not** test browser WebRTC, ICE, DTLS-SRTP, TURN,
SRTP, Opus or browser microphone handling.

An unknown synthetic destination returned 404. Public SSH, Kubernetes API and
kubelet connection attempts failed from the peer; an independent untrusted
source could not connect to the SIP/TLS/WSS listeners. The control APIs stayed
private. After replacing the Kamailio process, a fresh verified WSS call returned
248 of 250 audio frames exactly. Existing-call survival was not tested.

The initial minimal FreeSWITCH fixture omitted the explicit Sofia RTP timer.
A fixed 48,000-sample / 8 kHz WAV reached the peer faster than its six-second
source duration. A kernel timerfd override alone did not fix it. Explicitly
selecting `rtp-timer-name=soft` restored pacing; this setting already existed in
the operator's application source. The diagnostic core override was removed.
The [Sofia profile documentation](https://developer.signalwire.com/freeswitch/users-and-endpoints/sip-profiles/)
describes the RTP timer selection. No provider clock fault was established.

In the final reverse call, the peer received and echoed 300 of 300 known-tone
packets. The first-to-last interval was 5.978959 seconds (ideal: 5.98 seconds for
300 packets), with a median gap of 19.995 ms. The two-channel FreeSWITCH recording
contained both directions with tone correlation 0.999963. ACK and BYE completed.
This validates the bounded source/return path, not general voice quality or latency.

Cleanup is complete with independent baseline readback. Both temporary CLO VMs,
their boot volumes, the owned NAT, the Rancher cluster/config and the external
peer with its IPv4/firewall/key were deleted. The existing reusable test IPv4
is preserved; this run allocated no new CLO public address. The permanent management VM and existing external
monitoring remain outside the disposable stand. Raw captures, private image
archives, addresses, credentials and resource identities are not published.
[Sanitized measurements](voip-2026-11-18.json).

## Boundaries

The reusable runtime charts, address discovery, browser/real-operator acceptance,
DTMF, re-INVITE/hold, load, soak and telephony failover remain separate work.
The existing HTTP controller does not preserve SIP dialogues or active RTP calls.
The separate native-volume expansion failure still blocks CSI production
acceptance. No production migration is implied by these network results.
