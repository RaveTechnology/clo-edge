# Browser WebRTC sample — 19 November 2026

**Bounded synthetic sample passed; production acceptance remains pending.**

One disposable native CLO VM ran public Kamailio/rtpengine and private
FreeSWITCH on a Docker bridge. A separate local Chrome instance used SIP.js,
a generated microphone WAV and its existing NAT/VPN path. Administrative ports
and the FreeSWITCH backend were not exposed. The test allocated no new public
IPv4: an existing reserved address was attached after the persistent guard.

| Call | Established | Captured decoded receiver audio |
| --- | ---: | ---: |
| Browser → FreeSWITCH echo | 73.435 s | 46.251 s |
| FreeSWITCH → registered browser | 74.013 s | 47.360 s |
| Fresh call after reconnect | 8.642 s | 8.192 s |

The incoming call exceeded the SIP ACK timeout regression window. Successful
BYE processing ended the calls; the private FS channel was independently checked
absent. Negotiated media was PCMU/8000, with nominated successful ICE pairs,
connected DTLS and `SRTP_AEAD_AES_256_GCM`. The DTLS cipher was
`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`. Actual remote certificate DER retrieved
from the browser was hashed independently and matched the remote SDP fingerprint
of all three sessions. WSS used normal public certificate/IP validation, with no
certificate-ignore options or altered workstation trust store.

The outgoing received track contained the generated 600/1000 Hz microphone
signature. The incoming received track contained an independent 800 Hz FS source.
An independent 74.020 s FS stereo recording separated the received microphone
signature from the transmitted 800 Hz source. Analysis used normalized PCM16 RMS
and Goertzel amplitudes over a bounded ten-second segment after its first two
seconds, checking each target within ±3 Hz. The captured browser track was the
actual receiver track and was checked distinct from sender tracks. Decoded
samples are evidence of media delivery, not a test of physical speaker output.

A narrow private FS→relay media drop rule counted 482 packets. During its
5.120 s stable observation interval, browser received RTP did not advance,
while sent RTP advanced by 256 packets. The call stayed established;
after removing the rule, receipt advanced by 103 packets. The last three blocked
audio seconds had normalized RMS 0.000000. This control helps distinguish
received network audio from a local microphone loopback.

Wrong REGISTER credentials returned 403, an unknown synthetic destination returned
404, and the browser rejected the same WSS path with a separate self-signed
certificate on 8443 (`ERR_CERT_AUTHORITY_INVALID`). Explicit unregister/reconnect/
register completion was followed by a new call with decoded audio. A separate
local plain SIP/UDP check sent 250 PCMU packets and received 248 matching echo
frames with 248 unique received RTP sequences. That loopback check validates the
plain-media branch; the earlier [external SIP sample](voip-2026-11-18.md) covers a
different dated network experiment.

Changing egress addresses made a fixed client-IP pin unsuitable for this test
path. The temporary fixture used a private random WSS path, exact authorized
WebSocket connection tuples, REGISTER digest and ICE/DTLS-protected media. This
is a synthetic echo fixture, not a production tenant authorization design. It
kept an explicit Sofia `soft` RTP timer and explicit SDP origin/connection
replacement on plain replies. Reusable VoIP deployment charts were not qualified.

The browser, fixture and calls were stopped. The temporary VM, boot disk and NAT
were removed and the protected project baseline was restored. The reserved IPv4
remained free, and the permanent Rancher retained 2 vCPU / 8 GB. No additional
Telegram test was sent. No runtime archive, private audio/packet trace, native
identifier or credential is included here.

This run does not qualify Kubernetes/Canal networking, real tenant UI or credential
APIs, operator/PSTN interoperability, HA, active-call preservation, DTMF,
hold/re-INVITE, Opus, transcoding, TURN, load or a general NAT matrix. The separate
CSI native-volume expansion gate requires its own acceptance.
